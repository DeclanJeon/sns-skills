# 틱톡 팔로워 성장 플레이북

조회수를 하나의 점수로 보지 않는다. **관련 시청자에게 발견 → 약속한 답까지 시청 → 다음 편을 기대해서 팔로우**를 나누어 진단한다.

1. **기준선:** 제공된 주제, 타깃, 제작 가능 시간, 최근 영상과 인사이트를 확인한다. 없는 데이터는 미확인으로 둔다. 신규 계정도 데이터 없이 계획을 시작할 수 있다.
2. **우선순위 3개:** [유튜브 근거와 구조](references/tiktok-growth-research.md)를 읽고 관측 근거·가설·이번 주 행동을 각각 붙인다.
   - **신규/발견 부족:** 특정 독자와 반복 가능한 주제 하나를 고른다. Creator Search Insights가 있으면 콘텐츠 공백 후보를 읽고, 없으면 검색 제안이나 독자가 실제로 묻는 질문을 참고한다. 검색뿐 아니라 추천 유입 가능성도 열어 둔다.
   - **초반 이탈:** 질문·결과를 첫 장면에 드러내고, 긴 인사나 배경을 줄인다. 결과가 늦는 문제라면 결과 컷을 먼저 배치하는 안을 비교한다.
   - **시청되는데 팔로우 부족:** 영상이 목표 독자에게 닿았는지, 소개와 대표 영상에 다음 편을 기대할 이유가 있는지 본다. 반응한 질문에 후속편으로 답하되 첫 영상에서도 약속한 답은 준다.
3. **구조:** `문제 또는 결과 한 컷 → 실제 과정·증거 → 답이나 전후 비교`. 검색 표현은 읽는 사람이 이해하기 쉬운 곳에 자연스럽게 넣는다. 다른 사람의 대사·화면을 복제하지 않고 구조만 참고한다. 다음 편 예고는 실제 계획이 있을 때만 붙인다.
4. **4주 실험:** 1주 차에 기준선과 질문군을 정한다. 2주 차에 같은 질문군의 비교 가능한 영상을 계획한다. 3주 차에 첫 컷·설명 순서·후속편 예고 중 하나만 바꾼다. 4주 차에 게시 후 관측 기간을 맞춰 비교하고 유지·수정·중단할 것을 정한다. 횟수는 제작 여력에 맞춘다.
5. **측정:** 볼 수 있는 경우 검색 유입·검색어, 평균 시청 시간·완주/유지, 프로필 조회·계정 순증 팔로워를 따로 기록한다. 시청 시간과 완주는 비슷한 길이의 영상끼리 비교한다. 게시물별 귀속을 확인할 수 없으면 계정 단위 변화로만 기록한다. 최소한 주간 팔로워 수와 실험 내역을 남기고, 한두 게시물 성과로 인과를 단정하지 않는다.

최신 사례 요청 시 `flucto-media-research`의 현재 Flucto CLI 검색 절차로 다시 찾고 자막·공개 설명·자기보고를 구분한다. ‘200뷰 감옥’, 특정 게시 시각·횟수, 알고리즘 가중치, 팔로워 달성 기간을 공식 규칙이나 보장으로 제시하지 않는다.

전략과 초안 전용이다. 게시, 댓글·DM 전송, 팔로우, 계정 변경을 실행하지 않는다. 팔로워 구매·맞팔 품앗이·대량 자동화 대신 목표 독자에게 유용한 콘텐츠를 실험한다.
